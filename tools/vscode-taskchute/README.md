# TaskChute for VS Code (開発メモ)

TaskChute2 のスタートアップガイドの仕様を VS Code に移植した拡張機能。

## 構成

ビルド不要の素の JavaScript。TypeScript もバンドラも使っていないので、
ファイルを直したら「開発者: ウィンドウの再読み込み」だけで反映される。

```
src/
  extension.js   起動処理・コマンド登録
  panel.js       メイン画面 (Webview) のホスト。状態はすべてここが持つ
  model.js       純粋な計算。VS Code に依存しないので node から直接テストできる
  store.js       .taskchute/ 以下の読み書き
  dailyNote.js   デイリーノートの生成
  taskNote.js    タスクに紐づけるメモの生成とテンプレート
  ics.js         ICS (iCalendar) の取り込み
media/
  main.js        Webview 側の描画とキーボード操作
  main.css       スタイル (色は VS Code のテーマ変数を使う)
```

## インストール方法

環境フォルダ (`30_note`) の直下にある `install.ps1` が入れてくれる。

```powershell
powershell -ExecutionPolicy Bypass -File ../../install.ps1
```

`%USERPROFILE%\.vscode\extensions\local.taskchute-vscode-0.1.0` から、このフォルダへ
ディレクトリジャンクション (フォルダの別名。管理者権限なしで作れる) を張る。
張れない環境では自動でコピーに切り替わる (`-Copy` で明示もできる)。

環境フォルダの外に出るのはこのリンクだけ。ノートやタスクのデータには触らない。

別の PC へ移すときは `30_note` フォルダごとコピーして `install.ps1` を実行するだけ。
外部ライブラリを使っていないので `npm install` もネット接続も要らない。

## データ構造

`.taskchute/days/YYYY-MM-DD.json`:

```json
{
  "date": "2026-09-06",
  "updatedAt": "2026-09-06T10:40:00.000Z",
  "tasks": [
    {
      "id": "t...",           // 一意な ID
      "date": "2026-09-06",   // いつやるか。ファイル名と一致する
      "due": "2026-09-12",    // いつまでに。'' なら期限なし
      "section": "B",         // 節 (時間帯) A〜L
      "no": 20,               // ＃ 並べ替えると 10 刻みで振り直される
      "star": false,          // ★ 同じ節の中で先頭に並ぶ
      "project": "Work",
      "mode": "Focus",
      "name": "メールチェック",
      "estimateMin": 15,      // 見積 (分)。見積H は 60 で割って表示しているだけ
      "start": "09:14",
      "end": "09:41",         // 入っていれば完了。実績 = 終了 - 開始
      "sectionSort": "0825",  // 節内ソート順 (4桁)
      "notePath": "notes/2026-09-06-メールチェック.md", // 紐づけたメモ。'' なら無し
      "hint": "",             // タスク実行前のヒント
      "hintLink": "",         // 併記するリンク (ファイル/フォルダ/URL)
      "comment": "",          // タスク実行後のコメント
      "repeat": null,         // { kind, interval, weekdays, monthDay }
      "fixedSection": "",     // 繰り返しタスクの時間帯指定
      "seriesId": "",         // 繰り返しの系列 ID (重複複製の防止に使う)
      "calendarUid": "",      // ICS 取り込み時の照合キー
      "createdAt": "..."
    }
  ]
}
```

計算で出す項目はファイルに持たない (TaskChute で「編集不可」だった列と同じ考え)。

- ステータス (`□ ■ ◎ ★`) — 基準日と終了時刻から求める
- 曜 — 日付から求める
- 実績 — 終了 - 開始。終了が開始より前なら日をまたいだとみなす
- 期限の状態 (`overdue / today / soon / later / done`) — `due` と基準日から求める

## 絞り込みの設計

`panel.filter = { onlyPending, project, mode }` が持つ。適用場所は `visibleTasks()` の 1 箇所だけ。

**集計には絞り込みをかけない。** `daySummary` / `sectionSummary` / `forecast` は常に
`this.tasks` (一日ぶん全部) で計算する。表示を絞ったせいで一日の総量が小さく見えると、
「まだ余裕がある」と誤判断してしまうため。画面には `filter.shown / filter.total` を渡して、
一部だけ見ていることが分かるようにしている。

`onlyPending` は「完了」と「翌日以降」を落とす。積み残し (過去の未完了) は残す
— 終了予定時刻に効いている以上、隠すと辻褄が合わなくなるため。

## 表示言語

画面に出る文字列はすべて英語。日本語のまま残すのは、README、
ノートのテンプレート (`80_tamplate/`)、ソースのコメント、そしてユーザが入力したデータ。

曜日は 2 系統ある。`WEEKDAY_JA` はノートのテンプレートに差し込む用、
`WEEKDAY_EN` は画面に出す用。`weekdayJa()` を UI で使わないこと。

## オリジナルとの違い

| 項目 | TaskChute2 (Excel) | ここ |
| --- | --- | --- |
| 操作の入口 | メニューとコマンドボタン (マウス) | キーボードのみ。NORMAL / EDIT のモード制で、押すボタンは一切置かない |
| 繰り返しの印 | タスク名の末尾に `(repeats)` を書く | `repeat` フィールドで持ち、画面には `(repeats)` と表示 |
| 時間帯指定 | タスク名の先頭に `【B】` を書く | `fixedSection` フィールドで持ち、画面には `【B】` と表示 |
| 月日と曜 | 別々の列 | 1 列にまとめて `09/06 Sun` と表示 |
| 見積 | H と M の 2 列が連動 | 分の 1 列。`1.5h` `1:30` と打っても分に直る |
| 並べ替えの3種類 | セルの着色・行高の再計算の有無で速度が変わる | 見た目の再計算がないので速度差はない。「区切り」の先送りの有無だけが実質的な違い |
| セル高さ | 見積時間に応じて変わる | 未実装 (全行同じ高さ) |
| 検索入力 | ダイアログで1件ずつ候補を提示 | 過去の全タスク名を一覧から絞り込み。実績の平均時間も表示する |
| 見積シミュレーション | 完了タスクが1件以上必要 | 完了が無くても現在時刻を起点に計算する |
| 実行中の表示 | 特になし | 行を着色し、`実績` 欄に経過時間を出す (20 秒ごと更新) |
| 期限 | 無い (Project や名前に書く) | `due` として持ち、色分けと件数警告に使う |
| タスクのメモ | ヒント欄のハイパーリンク | `notePath` で .md を紐づけ、テンプレートから生成する |

## 画面側 (media/main.js) の作り

`ui` オブジェクトが画面の状態をすべて持つ。

```
mode         'normal' | 'edit'
rowId, col   カーソル位置 (行 id と列キー)
draft        編集中の文字列
combo        { items, index }  候補リスト
calendar     { cursor }        カレンダーが見ている日
showAllCols  \ キーで隠し列も出しているか
```

通常モードではセルを `<span>` として描く。編集モードのときだけ、カーソル位置のセルに
`<input>` を 1 つだけ差し込む。入力欄がひとつも無い状態を作れるので、
`document` の keydown だけで 1 文字キーのコマンドを取りこぼしなく受けられる。

`state` は拡張機能から丸ごと送られてくる。編集中に定期更新が届いたときは、
入力欄を壊さないようヘッダだけ差し替える。確定時は返事を待たず手元の state も
書き換えるので、表示が一拍遅れない (月日と見積だけは拡張機能側で解釈するため返事に任せる)。

列は `config.json` の `columns` で決まる。`Task` (作業内容) だけ幅を指定せず、
`table-layout: fixed` の余りを吸わせて可変にしている。

## テスト

**移行先の PC でまず最初に流すもの。** VS Code は要らず、node だけで動く。

```bash
node tools/vscode-taskchute/test/run.js
```

- `test/model.test.js` (47 件) — 日付と期限の短縮入力、見積の書式、時刻と実績の計算、
  ステータス記号、節の判定と現在の節、終了予定時刻、節別サマリーの色分け、並べ替え順、
  区切りの先送り、繰り返しの次回日と複製、シミュレーション、1日1ファイルの往復、
  範囲外への移動、タスク名の索引、デイリーノートとタスクメモの生成、ICS の解析
- `test/panel.test.js` (41 件) — `vscode` API をスタブに差し替えて `panel.js` を通しで動かす。
  Webview への状態送信、打刻、繰り返しの自動複製、日付変更でのファイル移動、並べ替え、
  基準日の移動、期限の設定と解除、3種類の絞り込みと集計への非干渉、メモの作成と付け替え、
  削除の確認、検索入力まで

一時フォルダを使うので、実際のノートやタスクのデータには触らない。
